# 听见 · 新闻简报

## 要解决的问题

新闻来源多、重复浏览耗时。用户需要围绕自己的兴趣快速阅读近期新闻，保留阅读状态，并在需要时得到简短摘要与参考分析。

## 当前交付（0.4.3 三步卡片版）

- 点「听见顾问」开始：应用依次推送三张**固定模板卡片**收集偏好
  - ① 兴趣主题：最多三个，选择顺序即优先级（支持自定义主题）
  - ② 阅读目的：若干选项，也可「跳过」
  - ③ 推送时间：若干时点，或「按需阅读」
- 每张卡片的选择写回 `accounts/device/pref-answer.json`，应用校验后进入下一步
- 三步选完 → 写入 `accounts/device/state.json` → 立即抓取 RSS → 语义筛选最多八条 → 生成 100–200 字今日简报
- 支持减少此类推荐（可撤销）、主题标签、来源链接、通知与 30 天阅读历史

## 当前完成标准

在 OctoSense 原生窗口完成：三步卡片收集偏好 → 应用保存 → 立即抓取并生成简报；可从结果回到原文；模型额度耗尽时给出明确提示。摘要只使用官方宿主接口，不使用外部新闻生成后端。

## 暂未实现

后台定时、语音生成或播放、自动追问、英文翻译、语义事件合并、跨来源事实核验、可靠重要性判断、可执行的应用 Agent 工具。当前产品名「听见」不代表已经支持语音。

## 已知限制（如实说明）

- **应用读不到「Ask <app>」面板里的自由输入**：Shell 的面板使用 instance `shell-ask`，而应用 `octos.session.open` 使用 `card.<app id>-gN`；`octos.session.history` 只合并调用方自身 instance 的 person lane（`crates/app-peers/src/broker.rs:3144-3145`）。因此偏好收集由应用主导，不经过该面板。
- **Agent 未被调用**：manifest 保留 `agent.profile=read-only`、`tools=[ask_user_question]`，但当前版本的偏好流程不经过它（保留声明以备后续自然语言入口）。

## 关于接口适配的说明

原始设想是「通过 Ask 面板与 agent 对话 → agent 分析意图 → 弹出 AppCard → 用户确认 → 应用保存」。在当前 shell 契约下，这条链有两处不通：
1. 应用无法读取面板 person lane（见上）；
2. `glance` 是**应用**的能力，agent 没有 glance，无法自行弹出 AppCard，只能由应用发布。

因此本版改为**应用主导**：应用自己推送三张卡片、自己校验与落盘。闭环可演示，但并非字面意义的「agent 弹卡片」。
